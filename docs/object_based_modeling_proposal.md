# ALLUVSIM and ResMill Porosity Ground Truth Implementation Brief

## 1. Context

The current study compares SGSIM with one or more ML-based spatial interpolation methods. The existing synthetic ground-truth fields were generated with SGSIM. This creates a potential methodological concern: a benchmark generated by SGSIM may favor SGSIM because its covariance structure and distributional assumptions are consistent with the reconstruction method.

Add an independent family of channelized synthetic ground truths generated with the ALLUVSIM methodology through ResMill. Treat this as a robustness test against the data-generating mechanism, not as an attempt to construct a field-calibrated reservoir model.

Use the following terminology in code, documentation, and manuscript drafts:

- `event-based fluvial realization`
- `channelized reservoir realization`
- `ALLUVSIM-based ground truth`
- `independently generated channelized ground truth`

Do not describe the models as exact geological truth, fully process-based models, or strict Boolean OBM. ResMill's `ChannelLayer` is better described as event-based or pseudo-process-based.

## 2. Objective

Generate reproducible continuous porosity ground-truth fields whose large-scale architecture is independent of SGSIM. Use them to compare SGSIM and ML interpolation under identical observation and evaluation conditions.

The implementation must:

1. Generate channelized facies architecture with `resmill.ChannelLayer`.
2. Export continuous porosity and facies arrays.
3. Generate multiple geological realizations using fixed, recorded seeds.
4. Apply exactly the same observation masks to SGSIM and ML methods.
5. Evaluate point accuracy and at least one spatial-structure metric.
6. Preserve all parameters, software versions, and seeds needed for exact reruns.

## 3. Non-goals

Do not expand the task into:

- field-scale reservoir calibration or history matching;
- conditioning the geological generator to actual wells;
- permeability generation or flow simulation;
- Petrel, RMS, Eclipse, or commercial software integration;
- modification or reimplementation of ALLUVSIM or ResMill;
- validation of the depositional simulator itself.

The required output is a benchmark dataset for porosity interpolation only.

## 4. Method and references

Use ResMill as the Python implementation and cite the ALLUVSIM paper as the primary methodological reference.

- Pyrcz, M. J., Boisvert, J. B., and Deutsch, C. V. (2009), *ALLUVSIM: A program for event-based stochastic modeling of fluvial depositional systems*. Computers & Geosciences, 35(8), 1671-1685. https://doi.org/10.1016/j.cageo.2008.09.012
- ALLUVSIM User Guide: https://ccg-server.engineering.ualberta.ca/CCG%20Publications/CCG%20Guidebooks/Vol%205%20User%20Guide%20to%20Alluvsim%20Program.pdf
- ResMill repository: https://github.com/SciLM-ai/ResMill
- ResMill package: https://pypi.org/project/resmill/

ResMill is a recent implementation. Record and freeze both the installed package version and Git commit hash. Do not rely on a floating latest version in the final experiment.

## 5. Ground-truth generation

### 5.1 Required ResMill component

Use:

```python
resmill.ChannelLayer
```

Do not use:

```python
resmill.GaussianLayer
```

`GaussianLayer` uses SGS heterogeneity and would weaken the purpose of the independent benchmark.

### 5.2 Initial grid

Use these defaults for the first working implementation:

```yaml
grid:
  nx: 128
  ny: 128
  nz: 16
  x_len: 1280.0
  y_len: 1280.0
  z_len: 16.0
  top_depth: 0.0
```

This corresponds to nominal cells of 10 m by 10 m by 1 m. If the existing SGSIM experiment uses a different grid, match that grid where practical and record the change in configuration.

### 5.3 Geological scenarios

Required primary scenario:

```text
CB_JIGSAW
```

This provides a moderate-net-to-gross, amalgamated/interlocking channel architecture.

Optional sensitivity scenario:

```text
PV_SHOESTRING
```

This provides lower-net-to-gross, more isolated sinuous channel bodies.

Priority under limited compute:

1. Generate at least 30 `CB_JIGSAW` geological realizations.
2. Add multiple sampling seeds per realization.
3. Add multiple sampling densities.
4. Only then add `PV_SHOESTRING`.

### 5.4 Porosity model

Use `ChannelLayer.poro_mat` as the continuous porosity truth. The intended conceptual structure is:

```text
porosity(x) = facies_base_porosity
              * depositional_position_trend
              * event_quality_multiplier
              * local_correlated_texture
```

Recommended initial parameters:

```yaml
porosity:
  poro_noise_std: 0.08
  poro_noise_range: 5.0
  valid_min: 0.0
  valid_max: 0.5
```

Use the default ResMill facies-property table initially. Do not tune parameters repeatedly to obtain visually preferred realizations. Change parameters only to fix a documented numerical failure or degenerate configuration.

The small correlated component does not define the principal geology. Large-scale geometry and nonstationarity must come from facies architecture, depositional position, and event hierarchy.

### 5.5 Number of realizations

Minimum:

```yaml
geological_seeds:
  start: 0
  stop_exclusive: 30
```

Do not select only visually attractive seeds. Generate the complete predefined seed range. Define exclusion criteria before reviewing results, and log every excluded realization and reason.

### 5.6 Two-dimensional benchmark rule

If the interpolation experiment is 2D, create each model in 3D and extract a slice using one fixed rule, for example:

```python
slice_index = nz // 2
porosity_2d = porosity_3d[:, :, slice_index]
facies_2d = facies_3d[:, :, slice_index]
```

Use the same slice rule for all realizations. Do not inspect the models and manually choose a different slice for each seed.

## 6. Minimal generation scaffold

Use this only as a starting point. Confirm the API against the frozen ResMill version.

```python
from pathlib import Path
import json
import numpy as np
import resmill as rm
from resmill.layers.channel import CB_JIGSAW

GRID = {
    "nx": 128,
    "ny": 128,
    "nz": 16,
    "x_len": 1280.0,
    "y_len": 1280.0,
    "z_len": 16.0,
    "top_depth": 0.0,
}

OUTPUT_DIR = Path("outputs/obm_ground_truth")
OUTPUT_DIR.mkdir(parents=True, exist_ok=True)

manifest = []

for seed in range(30):
    model = rm.ChannelLayer(**GRID)
    model.create_geology(
        seed=seed,
        poro_noise_std=0.08,
        poro_noise_range=5.0,
        **CB_JIGSAW,
    )

    porosity_3d = model.poro_mat.astype(np.float32)
    facies_3d = model.facies.astype(np.int8)

    slice_index = GRID["nz"] // 2
    porosity_2d = porosity_3d[:, :, slice_index]
    facies_2d = facies_3d[:, :, slice_index]

    stem = f"cb_jigsaw_seed_{seed:03d}"
    np.save(OUTPUT_DIR / f"{stem}_porosity_3d.npy", porosity_3d)
    np.save(OUTPUT_DIR / f"{stem}_facies_3d.npy", facies_3d)
    np.save(OUTPUT_DIR / f"{stem}_porosity_2d.npy", porosity_2d)
    np.save(OUTPUT_DIR / f"{stem}_facies_2d.npy", facies_2d)

    manifest.append({
        "id": stem,
        "geological_seed": seed,
        "preset": "CB_JIGSAW",
        "slice_index": slice_index,
        "shape_3d": list(porosity_3d.shape),
        "porosity_min": float(porosity_3d.min()),
        "porosity_max": float(porosity_3d.max()),
        "porosity_mean": float(porosity_3d.mean()),
        "porosity_std": float(porosity_3d.std()),
    })

with open(OUTPUT_DIR / "manifest.json", "w", encoding="utf-8") as f:
    json.dump(manifest, f, indent=2)
```

## 7. Sampling and comparison protocol

### 7.1 Separate random seeds

Keep these seed types separate:

- `geological_seed`: generates the reservoir truth;
- `sampling_seed`: generates observed locations;
- `method_seed`: controls stochastic SGSIM or ML behavior.

Store all three in result metadata.

### 7.2 Fair-input requirement

For each truth and sampling replicate, SGSIM and ML must receive:

- identical observation coordinates;
- identical observed porosity values;
- identical spatial domain and grid;
- identical training and evaluation masks;
- identical auxiliary variables, if any.

Do not give the facies map to ML unless it is also incorporated into the SGSIM workflow in a methodologically comparable way. The recommended initial experiment hides the facies map from both interpolation methods and uses it only to generate and diagnose the truth.

Do not estimate SGSIM variograms, distributions, or transformation parameters from the exhaustive truth. Estimate them using only the sampled observations available to the interpolation methods.

### 7.3 Sampling density

Recommended sensitivity levels:

```yaml
sampling_density:
  sparse: 0.005
  medium: 0.01
  dense: 0.02
```

If the existing study already uses different densities, preserve the existing design. Apply it identically to all methods.

Use at least three sampling seeds per geological realization when computationally feasible. If relevant to the existing study, add a clustered or well-like sampling design as a sensitivity case rather than relying only on uniformly random cells.

### 7.4 SGSIM prediction used for point metrics

Do not compare a deterministic ML prediction to one arbitrary SGSIM realization. For point-prediction metrics, use the conditional SGSIM ensemble mean, also called the E-type estimate.

If both methods generate predictive ensembles, evaluate uncertainty separately from point accuracy.

## 8. Evaluation

### 8.1 Required point metrics

- RMSE
- MAE
- R-squared

Report realization-level results and aggregated distributions. Prefer paired comparisons because SGSIM and ML use the same truth and observation mask.

### 8.2 Required spatial metric

Include at least one of:

- variogram reproduction error;
- SSIM or multiscale SSIM;
- connected-component size error after thresholding porosity;
- directional connectivity function;
- high-porosity percolation or connectivity error.

Choose the metric and threshold before examining comparative results. Apply the same threshold rule to every method and realization.

### 8.3 Optional uncertainty metrics

Use these only if both approaches provide meaningful predictive ensembles:

- CRPS;
- prediction interval coverage;
- interval width;
- interval score.

Report point accuracy and uncertainty calibration in separate tables.

## 9. Quality control

Run automated QC for every generated realization.

Required checks:

- expected array shape and axis orientation;
- no NaN or infinite values;
- porosity within the configured physical range;
- valid facies codes;
- global porosity mean and standard deviation;
- facies proportions and net-to-gross;
- porosity distribution by facies;
- no duplicate realizations across geological seeds;
- fixed 2D slice rule applied correctly;
- generated files match the manifest.

Create representative diagnostic plots for a predefined subset of seeds, such as `0`, `10`, and `20`:

- porosity slice;
- facies slice;
- porosity histogram;
- porosity distribution by facies;
- directional variogram;
- thresholded connectivity map.

Do not use visual inspection to retain favorable seeds. If a realization fails a predefined QC rule, record the exclusion and exact reason in the manifest.

## 13. Suggested manuscript statement

Use or adapt the following:

> Because the original synthetic truth models were generated using SGSIM, their covariance structure may favor variogram-based reconstruction. We therefore conducted an additional robustness experiment using independently generated event-based fluvial reservoir models based on the ALLUVSIM framework. The resulting porosity fields contain curvilinear facies boundaries, connected channel bodies, depositional trends, and facies-dependent non-Gaussian distributions that are not imposed by the SGSIM algorithm. Identical sampling locations and input variables were used for both interpolation methods.

Interpret results by benchmark family. The SGSIM-generated benchmark represents performance under a variogram-based, approximately multi-Gaussian data-generating model. The ALLUVSIM-based benchmark evaluates transfer robustness to channelized, facies-controlled, non-Gaussian geology. Do not generalize either benchmark to all geological environments, and do not claim that the synthetic experiment replaces real-field validation.

## 14. Implementation order

1. Create a clean Python environment and install ResMill.
2. Record the exact version and Git commit.
3. Run a small-grid `CB_JIGSAW` smoke test.
4. Verify `poro_mat`, `facies`, axes, and value ranges.
5. Generate the complete predefined geological seed range.
6. Extract the fixed 2D slice if the study is 2D.
7. Generate observation masks independently of the geological generator.
8. Run automatic QC and write the manifest.
9. Run SGSIM and ML with identical conditioning data.
10. Generate paired metrics and realization-level summaries.
11. Verify an end-to-end rerun in a clean environment.

Any unresolved design choice must be exposed as a configuration parameter rather than silently hard-coded. Grid resolution, geological preset, realization count, porosity-noise settings, slice rule, sampling density, and evaluation threshold must be frozen before comparative results are inspected.
